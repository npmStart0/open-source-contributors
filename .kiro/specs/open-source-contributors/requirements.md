# Requirements — Open Source Contributors

## מבוא

מסמך זה מגדיר את הדרישות הפונקציונליות והלא-פונקציונליות לגרסה 1.0 של
Open Source Contributors: אתר סטטי בקוד פתוח להצגת פרופילי תורמים, עם הוספת
פרופילים דרך Pull Request בלבד, ללא שינוי בקוד React. כל דרישה מלווה בקריטריוני
קבלה בפורמט EARS.

## דרישות

### דרישה 1 — הצגת ספריית תורמים (Contributor Directory)

**User Story:** כמבקר באתר, אני רוצה לראות רשת של כרטיסי תורמים, כדי להכיר את
חברי הקהילה.

**קריטריוני קבלה:**
1. WHEN דף הבית נטען THEN המערכת SHALL להציג רשת כרטיסים עבור כל התורמים התקינים.
2. כל כרטיס SHALL להציג שם, username, תיאור קצר (אם קיים) ורשימת טכנולוגיות (אם קיימת). אין תמונת פרופיל.
3. WHEN המשתמש לוחץ על קישור GitHub בכרטיס THEN המערכת SHALL לפתוח את הפרופיל הציבורי בכתובת `https://github.com/{username}`.
4. דף הבית SHALL לכלול כותרת פרויקט, תיאור קצר, כפתור `Join the Community` וקישור לדף `How to Contribute`.

### דרישה 2 — חיפוש לפי שם ו-username

**User Story:** כמבקר, אני רוצה לחפש תורם לפי שם או username, כדי למצוא אדם מסוים.

**קריטריוני קבלה:**
1. WHEN המשתמש מקליד מחרוזת חיפוש THEN המערכת SHALL להציג רק תורמים שהשם או ה-username שלהם מכיל את המחרוזת (התאמה חלקית).
2. ההתאמה SHALL להיות לא רגישה לאותיות גדולות/קטנות ועם נרמול רווחים.
3. WHEN שדה החיפוש ריק THEN המערכת SHALL להציג את כל התורמים.
4. החיפוש SHALL להתבצע מקומית ללא בקשת רשת לכל שינוי.

### דרישה 3 — סינון לפי טכנולוגיות

**User Story:** כמבקר, אני רוצה לסנן תורמים לפי טכנולוגיות, כדי למצוא מפתחים בתחום מסוים.

**קריטריוני קבלה:**
1. WHEN המשתמש בוחר טכנולוגיה אחת THEN המערכת SHALL להציג רק תורמים שרשימת הטכנולוגיות שלהם כוללת אותה.
2. WHEN המשתמש בוחר מספר טכנולוגיות THEN המערכת SHALL להציג תורם אם הוא תואם לפחות לאחת מהן (OR בין טכנולוגיות).
3. WHEN קיימים גם חיפוש וגם מסנן טכנולוגיות THEN המערכת SHALL לדרוש התאמה לשניהם (AND בין חיפוש למסנן).
4. WHEN המשתמש מנקה את המסננים THEN המערכת SHALL להציג את כל התורמים.
5. פעולת הסינון SHALL לא לשנות את מערך הנתונים המקורי.

### דרישה 4 — פונקציית עזר `filterContributors`

**User Story:** כמפתח, אני רוצה פונקציית עזר טהורה לחיפוש וסינון, כדי לבדוק את הלוגיקה בבידוד.

**קריטריוני קבלה:**
1. המערכת SHALL לספק פונקציה `filterContributors(contributors, query, selectedSkills)`.
2. הפונקציה SHALL להחזיר מערך חדש ולא לשנות את הקלט.
3. הפונקציה SHALL ליישם את כללי החיפוש (דרישה 2) והסינון (דרישה 3).
4. WHEN `query` ריק ו-`selectedSkills` ריק THEN הפונקציה SHALL להחזיר את כל התורמים.

### דרישה 5 — Empty State

**User Story:** כמבקר, אני רוצה לקבל חיווי ברור כשאין תוצאות, כדי להבין שהחיפוש לא החזיר התאמות.

**קריטריוני קבלה:**
1. WHEN החיפוש/סינון אינו מחזיר תורמים THEN המערכת SHALL להציג הודעת Empty State.

> הערה: גרסה 1.0 אינה כוללת תמונות פרופיל/avatar כלל.
2. הודעת ה-Empty State SHALL להיות מתורגמת לשפה הנבחרת.

### דרישה 6 — דף הוראות תרומה (Contribution Guide)

**User Story:** כתורם פוטנציאלי, אני רוצה דף הוראות מלא, כדי להוסיף פרופיל ללא עזרה נוספת.

**קריטריוני קבלה:**
1. הדף SHALL להסביר את מטרת הפרויקט ואת תהליך Fork / Branch / Commit / Pull Request.
2. הדף SHALL לכלול דוגמת JSON תקינה.
3. הדף SHALL לתעד את כללי הוולידציה ופתרונות לתקלות נפוצות (username כפול, כישלון CI).
4. הדף SHALL לכלול קישורים ל-README, ל-CONTRIBUTING ולמאגר GitHub.

### דרישה 7 — דו-לשוניות וכיווניות (he/en, RTL/LTR)

**User Story:** כמבקר דובר עברית או אנגלית, אני רוצה להחליף שפה, כדי לקרוא את הממשק בשפה שלי.

**קריטריוני קבלה:**
1. המערכת SHALL לתמוך בעברית ובאנגלית עם מחליף שפה.
2. WHEN נבחרת עברית THEN המערכת SHALL להגדיר `dir="rtl"` ו-`lang="he"`.
3. WHEN נבחרת אנגלית THEN המערכת SHALL להגדיר `dir="ltr"` ו-`lang="en"`.
4. כל טקסטי הממשק SHALL להישמר במילונים מרכזיים ולא קשיחים בתוך רכיבים.
5. טקסט שסיפק התורם (name, bio) SHALL להישאר ללא שינוי ללא קשר לשפת הממשק.

### דרישה 8 — מודל נתונים וולידציה

**User Story:** כמתחזק, אני רוצה שכל פרופיל יעבור ולידציה, כדי להבטיח איכות ועקביות.

**קריטריוני קבלה:**
1. כל תורם SHALL להיות מיוצג בקובץ `contributors/{username}.json`.
2. השדות `username` ו-`name` SHALL להיות חובה; `bio` ו-`skills` אופציונליים.
3. `username` SHALL להכיל אותיות לטיניות קטנות, מספרים ומקפים בלבד, עם אורך מוגבל.
4. `name` SHALL להיות מחרוזת לא ריקה עד 80 תווים; `bio` עד 280 תווים; `skills` מערך עד 10 פריטים ללא כפילויות.
5. שם הקובץ SHALL להתאים בדיוק לשדה `username`.
6. המערכת SHALL לדחות: JSON לא תקין, שדות חובה חסרים, טיפוס שגוי, username כפול (ללא תלות ברישיות), אי-התאמה בין שם קובץ ל-username, ושדות שאינם בסכמה.
7. כתובת פרופיל ה-GitHub SHALL להיווצר מתוך ה-username המאומת (`https://github.com/{username}`).

### דרישה 9 — בנייה בזמן build ושירות נתונים

**User Story:** כמפתח, אני רוצה שהנתונים ייווצרו בזמן build, כדי שלא יידרש שינוי קוד React בהוספת תורם.

**קריטריוני קבלה:**
1. סקריפט Node.js SHALL לקרוא את קובצי `contributors/`, לאמת אותם ולהפיק מודול נתונים.
2. WHEN קובץ מקור אינו תקין THEN תהליך הבנייה SHALL להיכשל בכישלון מפורש.
3. אין לערוך את מודול הנתונים שנוצר ידנית.
4. הוספת תורם SHALL לא לדרוש שינוי בקוד מקור של React.

### דרישה 10 — CI/CD ופריסה

**User Story:** כמתחזק, אני רוצה בדיקות אוטומטיות ופריסה, כדי לשמור על איכות ולפרסם אוטומטית.

**קריטריוני קבלה:**
1. WHEN נפתח Pull Request THEN CI SHALL להריץ: `npm ci`, `npm run lint`, `npm run validate:contributors`, `npm run test -- --run`, `npm run build`.
2. WHEN נתונים לא תקינים או build נכשל THEN ה-PR SHALL לא לעבור את בדיקות ה-CI.
3. WHEN מתבצע מיזוג ל-`main` THEN workflow הפריסה SHALL לבנות ולפרסם ל-GitHub Pages.
4. workflow הבדיקות SHALL להיות נפרד מ-workflow הפריסה.
5. workflow הפריסה SHALL להשתמש בהרשאות מינימליות ולא לחשוף credentials ל-PRs חיצוניים.
6. פעולות GitHub חיצוניות SHALL להיות מקובעות לגרסה.

## דרישות לא-פונקציונליות

1. **ביצועים:** חיפוש וסינון מקומיים ללא בקשת רשת לכל שינוי.
2. **נגישות:** ניווט במקלדת, תוויות נגישות, ניגודיות ומבנה כותרות תקין.
3. **רספונסיביות:** תמיכה בנייד, טאבלט ומחשב.
4. **אבטחה:** ללא סודות בפרונטאנד; רינדור בטוח של תוכן תורם (ללא HTML לא מהימן).
5. **אמינות:** כישלון מפורש בבנייה כשנתוני המקור אינם תקינים.
6. **תחזוקה:** הפרדת אחריות, טיפוסים ברורים, תיעוד מעודכן.
7. **תאימות:** תמיכה בדפדפנים מודרניים.
8. **דו-לשוניות:** תרגומים מרכזיים ותמיכה מלאה ב-RTL ו-LTR.

## קריטריוני קבלה לגרסה 1.0 (סיכום)

- האתר נבנה בהצלחה ב-production.
- כל קובצי התורמים התקינים מוצגים בכרטיסים.
- חיפוש וסינון פועלים יחד (AND).
- כל כרטיס כולל קישור נכון לפרופיל GitHub.
- הממשק תומך בעברית ובאנגלית; הכיווניות מתעדכנת בהחלפת שפה.
- נתונים לא תקינים גורמים לכישלון בדיקות ה-CI; אין כפילויות username.
- כל הבדיקות עוברות; הפריסה ל-GitHub Pages מצליחה.
- תורם חדש יכול להוסיף פרופיל לפי README ללא שינוי בקוד React.
- המאגר כולל תיעוד ורישיון מתאימים.
